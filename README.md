сохранённые результаты находятся в `.ipynb`. Рядом лежат `.sql` с теми же
запросами и комментариями для чтения и запуска в PostgreSQL.

## 3. Запуск

1. Запустить PostgreSQL.
2. Из корня проекта установить зависимости:
   `python3 -m pip install -r requirements.txt`.
3. Открыть нужный `.ipynb` в VS Code с расширениями Python/Jupyter
   либо JupyterLab и выбрать Python с установленными зависимостями.
4. Выполнять **Run All** или ячейки сверху вниз.

Для новой базы порядок: **ЛР2 → ЛР3 → ЛР4 → ЛР5 → ЛР6 → ЛР7**.
Если `parking` уже создана и заполнена, для запросов можно сразу открыть ЛР5.
ЛР3 и ЛР4 создают таблицы и рассчитаны на первый запуск: существующие
таблицы автоматически не удаляются. Все семь ноутбуков ранее проверены
полным выполнением на отдельном PostgreSQL; результаты сохранены.

Подключение: `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` или `.pgpass`.
По умолчанию — `127.0.0.1:5432`, текущий пользователь ОС и база конкретного
ноутбука. `PGDATABASE` переопределяет базу; обычно его задавать не нужно.
Пароли не сохраняйте в ячейках.

В ЛР3/ЛР4 последняя ячейка сохраняет изменения. После ошибки или прерывания
сделайте `conn.rollback()` перед повтором. Учебный ноутбук ЛР5 в конце
откатывает временные изменения. Исходных данных для `sales` в проекте нет.

### SQL без Jupyter

В папке каждой лабы есть `.sql` с тем же именем, что у ноутбука.
Откройте его в Query Tool pgAdmin или запустите из корня проекта:

```sh
psql -X -v ON_ERROR_STOP=1 -d parking -f labs/lab06/lab6_parking_views.sql
psql -X -v ON_ERROR_STOP=1 -d parking -f labs/lab07/lab7_parking_routines.sql
```

Перед этим нужна база и данные ЛР2–ЛР3. ЛР4 для ЛР6–ЛР7 не обязательна.
Для создания самой базы подключитесь к `postgres` и выполняйте
`lab2_parking_db.sql` отдельно, вне транзакции. Если база уже существует,
пропустите создание. SQL ЛР3–ЛР4 создаёт таблицы один раз; не запускайте
оба формата подряд на одной уже подготовленной схеме.

| Работа | SQL-пример |
|---|---|
| ЛР2 | [Создание parking](labs/lab02/lab2_parking_db.sql) |
| ЛР3 | [Таблицы и данные](labs/lab03/lab3_parking.sql) |
| ЛР4 | [Массивы и JSON](labs/lab04/lab4_parking.sql) |
| ЛР5 | [Учебные примеры](labs/lab05/lab5_textbook_example.sql) · [Индивидуальные запросы](labs/lab05/lab5_parking_queries.sql) |
| ЛР6 | [Представления](labs/lab06/lab6_parking_views.sql) |
| ЛР7 | [Процедуры и функции](labs/lab07/lab7_parking_routines.sql) |

SQL ЛР3–ЛР7 содержит `BEGIN` и завершение транзакции. ЛР5 заканчивается
`ROLLBACK`; ЛР6–ЛР7 сохраняет определения, откатывая демонстрационные изменения.
После ошибки в pgAdmin выполните `ROLLBACK` перед повторным запуском.
Файлы проверены на отдельном PostgreSQL 17; ЛР6–ЛР7 также прошли повторный запуск.

Иллюстрации ЛР6–ЛР7 и картинки, извлечённые из PDF ЛР10, хранятся только
локально и не публикуются в Git. Их ссылки в Markdown работают в локальной
копии проекта; на GitHub эти изображения недоступны.
