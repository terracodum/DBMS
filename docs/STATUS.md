- Нумерацию изменил преподаватель; номера папок корректны.
- Учебные примеры разрешено переносить на parking.
- Лабораторные уже сданы; сейчас упорядочиваем материалы.
- Все 52 SQL-листинга Markdown-отчёта ЛР5 совпадают с ноутбуками.
- В 50 таблицах результатов ЛР5 значения совпали. В DISTINCT по маркам
  различается только порядок строк: локаль влияет на сортировку.

  (состояние после обеих частей ЛР4).

## 2. Известные расхождения

| Вопрос | Состояние |
|---|---|
| Отчёт ЛР2 включает таблицы и ограничения, ноутбук ЛР2 — только базу | Разделение исполнения пояснено; таблицы находятся в ноутбуке ЛР3 |
| В отчётах postgres / Russian_Russia.1251, в ноутбуке текущая роль и локаль template0 | Сохранён исторический отчёт; различие описано в договорённостях |
| 12 проверок целостности есть в отчёте ЛР3, но отсутствуют в ноутбуке | SQL и исторический протокол доступны в архиве; Run All ЛР3 их не воспроизводит |
| Правило сохранения финансовых документов против CASCADE по сотрудникам | Пользователь считает правило РГР более подходящим. Схема пока сохраняется как в сданных работах |
| Запрет пересечения договоров | В базовой схеме не реализован; отчёт об этом говорит. В архивной расширенной версии есть EXCLUDE; к текущей БД она не применялась |
| Варианты ЛР4 и DOCX | Основной Markdown выбран для дальнейшей работы; старые версии сохранены |
| Скриншоты в отчётах | Не переписываем требования задним числом; текстовые результаты не считаем автоматически эквивалентными скриншотам |

## 3. Что делать при следующих изменениях

Менять рабочий ноутбук и соответствующий основной Markdown согласованно.
Проверять результат на отдельной БД и затем пересобирать DOCX, когда нужен
новый отчёт. Изменение бизнес-правил и действующей схемы — отдельная задача;
не включать его скрытно в навигационную уборку.

Содержание DOCX и визуальное оформление страниц в этом ревью не проверялись.
