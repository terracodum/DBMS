## Учебные примеры

### 2.1 Число договоров по клиентам

Аналог `number_of_orders`: вместо заказов считаем договоры. `COUNT(c.contr_id)` при LEFT JOIN возвращает ноль для клиента без договоров. Имена столбцов задаются явно: `OR REPLACE` не позволяет переименовывать существующий столбец добавлением другого псевдонима; для этого есть `ALTER VIEW`.

Листинг: 2.1 Число договоров по клиентам — SQL

```sql
CREATE OR REPLACE VIEW lab6.v_client_contract_counts AS
SELECT cl.cl_id, cl.cl_name, COUNT(c.contr_id) AS contract_count
FROM public.clients cl
LEFT JOIN public.contracts c ON c.contr_client_id = cl.cl_id
GROUP BY cl.cl_id, cl.cl_name;
```

Сортировка задаётся во внешнем SELECT.

Листинг: 2.1 Число договоров по клиентам — SQL

```sql
SELECT * FROM lab6.v_client_contract_counts ORDER BY cl_id;
```

### 2.2 Суммарная стоимость договоров по категориям

Аналог `price_view`. Здесь суммируются суммы договоров, а не цены тарифов с разными периодами. `WITH DATA` сразу сохраняет результат. Повторный запуск обновляет снимок отдельной командой REFRESH.

Листинг: 2.2 Суммарная стоимость договоров по категориям — SQL

```sql
CREATE MATERIALIZED VIEW IF NOT EXISTS lab6.mv_category_amounts AS
SELECT cat.cat_id, cat.cat_name, COUNT(c.contr_id) AS contract_count,
       COALESCE(SUM(c.contr_amount), 0)::numeric(14,2) AS total_amount
FROM public.vehicle_categories cat
LEFT JOIN public.vehicles v ON v.veh_cat_id = cat.cat_id
LEFT JOIN public.contracts c ON c.contr_veh_id = v.veh_id
GROUP BY cat.cat_id, cat.cat_name
WITH DATA;
```

Материализованное представление обновляется явно.

Листинг: 2.2 Суммарная стоимость договоров по категориям — SQL

```sql
REFRESH MATERIALIZED VIEW lab6.mv_category_amounts;
```

LEFT JOIN оставляет категории без договоров.

Листинг: 2.2 Суммарная стоимость договоров по категориям — SQL

```sql
SELECT cat.cat_name, mv.contract_count, mv.total_amount
FROM public.vehicle_categories cat
LEFT JOIN lab6.mv_category_amounts mv ON mv.cat_id = cat.cat_id
ORDER BY cat.cat_id;
```

### 2.3 Клиенты со скидкой

Аналог `cust_view`. `WITH NO DATA` создаёт ненаполненное представление. До первого REFRESH чтение вызывает ошибку SQLSTATE 55000. На повторном запуске IF NOT EXISTS сохраняет уже созданный объект.

Листинг: 2.3 Клиенты со скидкой — SQL

```sql
CREATE MATERIALIZED VIEW IF NOT EXISTS lab6.mv_discount_clients AS
SELECT cl_id, cl_name, cl_type, cl_discount
FROM public.clients WHERE cl_discount > 0
WITH NO DATA;
```

Проверка до первого REFRESH вызывает ожидаемую ошибку SQLSTATE 55000. В ноутбуке используется SAVEPOINT: после ошибки выполняется ROLLBACK TO, что позволяет продолжить транзакцию и наполнить представление.

Теперь представление можно читать.

Листинг: 2.3 Клиенты со скидкой — SQL

```sql
REFRESH MATERIALIZED VIEW lab6.mv_discount_clients;
```

Код клиента разрешает равенства при сортировке.

Листинг: 2.3 Клиенты со скидкой — SQL

```sql
SELECT * FROM lab6.mv_discount_clients ORDER BY cl_discount, cl_id;
```

## Индивидуальные представления

### 3.1 Подробности договоров

Каждая строка — один договор: клиент, автомобиль, место и сумма. Значение статуса берётся из учебных данных; текущая дата не используется.

Листинг: 3.1 Подробности договоров — SQL

```sql
CREATE OR REPLACE VIEW lab6.v_contract_details AS
SELECT c.contr_id, c.contr_number, c.contr_client_id AS cl_id,
       cl.cl_name, cl.cl_type, v.veh_plate, cat.cat_name,
       p.pl_sector, p.pl_number, c.contr_amount, c.contr_status
FROM public.contracts c
JOIN public.clients cl ON cl.cl_id = c.contr_client_id
JOIN public.vehicles v ON v.veh_id = c.contr_veh_id
JOIN public.vehicle_categories cat ON cat.cat_id = v.veh_cat_id
JOIN public.places p ON p.pl_id = c.contr_place_id;
```

### 3.2 Расчёты по договорам

Платежи сначала группируются по договору, затем присоединяются. Это сохраняет одну строку на договор и не умножает его сумму на число квитанций. `balance` — сумма договора минус все платежи; отрицательное значение означает переплату. Штрафы и возвраты в этой учебной схеме отдельно не учитываются.

Листинг: 3.2 Расчёты по договорам — SQL

```sql
CREATE OR REPLACE VIEW lab6.v_contract_balances AS
SELECT d.*, COALESCE(p.paid_amount, 0)::numeric(14,2) AS paid_amount,
       (d.contr_amount - COALESCE(p.paid_amount, 0))::numeric(14,2) AS balance
FROM lab6.v_contract_details d
LEFT JOIN (
    SELECT pay_contr_id, SUM(pay_sum) AS paid_amount
    FROM public.payments GROUP BY pay_contr_id
) p ON p.pay_contr_id = d.contr_id;
```

Выводятся все договоры, включая полностью оплаченные.

Листинг: 3.2 Расчёты по договорам — SQL

```sql
SELECT contr_number, cl_name, contr_amount, paid_amount, balance
FROM lab6.v_contract_balances
ORDER BY contr_id;
```

## Запросы индивидуального задания

### 4.1 Выборка с вложенным запросом

Вывести договоры, сумма которых превышает среднюю сумму всех договоров. Основной и вложенный запросы обращаются к представлению.

Листинг: 4.1 Выборка с вложенным запросом — SQL

```sql
SELECT contr_number, cl_name, contr_amount
FROM lab6.v_contract_details
WHERE contr_amount > (SELECT AVG(contr_amount) FROM lab6.v_contract_details)
ORDER BY contr_id;
```

![Договоры с суммой выше средней](images/05_subquery.png)

### 4.2 Группировка и простая сортировка

Определить число клиентов со скидкой и среднюю скидку по типам клиентов. Простая сортировка — по одному полю, типу клиента.

Листинг: 4.2 Группировка и простая сортировка — SQL

```sql
SELECT cl_type, COUNT(*) AS client_count,
       ROUND(AVG(cl_discount), 2) AS average_discount
FROM lab6.mv_discount_clients
GROUP BY cl_type
ORDER BY cl_type;
```

![Число клиентов и средняя скидка по типам](images/06_group_sort.png)

### 4.3 Группировка и многоуровневая сортировка

По типу клиента и сектору определить число договоров и суммы начислений, оплаты и остатка. Сначала сортировать остаток по убыванию, затем начисления по убыванию, затем тип и сектор по возрастанию.

Листинг: 4.3 Группировка и многоуровневая сортировка — SQL

```sql
SELECT cl_type, pl_sector, COUNT(*) AS contract_count,
       SUM(contr_amount) AS total_amount, SUM(paid_amount) AS paid_amount,
       SUM(balance) AS balance
FROM lab6.v_contract_balances
GROUP BY cl_type, pl_sector
ORDER BY balance DESC, total_amount DESC, cl_type ASC, pl_sector ASC;
```

![Расчёты по типам клиентов и секторам](images/07_multilevel_sort.png)

## Проверка обновления материализованного представления

В savepoint временно увеличим сумму одного договора на 100. Обычное представление сразу покажет изменение, материализованное — после REFRESH. ROLLBACK TO отменяет и изменение договора, и обновление снимка.

Для демонстрации выбран договор с минимальным кодом. В savepoint его сумма увеличена на 100. Обычное представление сразу показало 327800,00 вместо 327700,00; материализованное сохранило 327700,00 до REFRESH. После REFRESH снимок также показал 327800,00. Откат к savepoint восстановил и исходную сумму договора, и содержимое снимка. Проверки assert подтвердили все переходы и восстановление данных.
