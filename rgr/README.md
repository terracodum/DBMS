# РГР «Автостоянка», вариант 11 — как всё запустить

## 0. Что показывать на защите

Открыть pgAdmin, подключиться к серверу, дальше по порядку.

| Что показать | Как |
|---|---|
| **1. База данных создана** | В навигаторе: Servers → PostgreSQL → Databases → `parking`. Вкладка **SQL** справа показывает инструкцию CREATE DATABASE, которой она создана |
| **2. Таблицы созданы, поля и типы определены** | Databases → parking → Schemas → public → **Tables (9)**. Раскрыть любую → Columns: видны поля и типы |
| **3. Связи между таблицами** | Раскрыть таблицу `contracts` → **Constraints**: пять внешних ключей. Либо ERD-схема (см. ниже) |
| **4. Ограничения целостности** | Там же в Constraints видны PK, UNIQUE и CHECK каждой таблицы |
| **5. Схема БД** | Tools → **ERD Tool** → правой кнопкой на `parking` → **ERD For Database** |
| **6. Всё это одним списком** | Query Tool на базе `parking` → открыть **`demo.sql`** и выполнять запросы по одному (выделить + F5) |

Файл `demo.sql` собран специально для показа: каждый его раздел подписан
пунктом задания и выводит доказательство прямо на экран — параметры базы,
список таблиц с числом полей, поля и типы таблицы договоров, 15 внешних
ключей с правилами ON DELETE / ON UPDATE, сводку по 51 ограничению и все
ограничения с определениями.

В конце файла — четыре запроса, которые **должны завершиться ошибкой**:
повтор госномера, скидка 50 %, отрицательная сумма квитанции и договор на
несуществующего клиента. Это и есть доказательство, что ограничения
целостности реально работают, а не просто записаны в скрипте. И два
запроса на реальных данных: расчёты по договорам с частичной оплатой и
журнал проездов, где у чужих машин клиент не определён.

Если попросят показать исходные скрипты — это `lab2_parking_db.sql`
(создание БД) и `lab3_parking_tables.sql` (таблицы, связи, ограничения).

## 1. Установка PostgreSQL

Скачать: https://www.postgresql.org/download/windows/ → «Download the installer»
→ **PostgreSQL 15.x или 16.x, Windows x86-64**.

При установке:

| Шаг мастера | Что выбрать |
|---|---|
| Каталог установки | оставить по умолчанию (`C:\Program Files\PostgreSQL\16`) |
| Компоненты | **все** — PostgreSQL Server, pgAdmin 4, Stack Builder, Command Line Tools |
| Каталог данных | по умолчанию |
| Пароль суперпользователя `postgres` | **postgres** (иначе передать свой пароль скрипту, см. ниже) |
| Порт | **5432** |
| Локаль | **Russian, Russia** |
| Stack Builder в конце | можно закрыть, дополнительное ПО не требуется |

pgAdmin 4 нужен обязательно: им строится ERD-схема базы данных для отчёта.

## 2. Автоматический прогон всех скриптов

```powershell
cd X:\Coding\work\DBMS\rgr
.\run_all.ps1
```

Если пароль суперпользователя отличается от `postgres`:

```powershell
.\run_all.ps1 -Password "ваш_пароль"
```

Скрипт сам найдёт `psql.exe`, выполнит файлы по порядку и сложит протоколы
выполнения в каталог `rgr\log`. Эти протоколы — готовый материал для
раздела 6 отчёта.

Если PowerShell откажется запускать скрипт, разрешить выполнение для
текущего сеанса:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## 3. Ручное выполнение в pgAdmin (так нагляднее для скриншотов)

1. Запустить pgAdmin 4, подключиться к серверу PostgreSQL.
2. Открыть Query Tool на базе `postgres`, выполнить `lab2_parking_db.sql` (F5).
3. Обновить узел Databases (правая кнопка → Refresh), открыть Query Tool
   уже на базе `parking`.
4. Выполнить `lab3_parking_tables.sql` целиком (F5).
5. Выполнить `lab4_parking_data.sql` — заполнение таблиц данными,
   обновление и удаление (удаления отменяются командой ROLLBACK).
6. `test\integrity_tests.sql` выполнять **по одной инструкции**: выделить
   инструкцию мышью и нажать F5. Каждая должна дать ошибку — это и есть
   результат проверки, снимок экрана каждой ошибки идёт в отчёт.
7. `test\structure_report.sql` — выполнять запросы по одному, результаты
   с вкладки Data Output вставить в отчёт.

## 4. Схема базы данных для отчёта

Главное меню **Tools → ERD Tool**, затем правой кнопкой на базе `parking`
→ **ERD For Database**. Полученную диаграмму сохранить как изображение
(кнопка Download image) и вставить в отчёт как рис. 6.

## 5. Состав файлов

**Основные файлы работы:**

| Файл | Назначение |
|---|---|
| `lab2_parking_db.sql` | лабораторная работа № 2 — создание базы данных `parking` |
| `lab3_parking_tables.sql` | лабораторная работа № 3 — 9 таблиц, ограничения UNIQUE / DEFAULT / CHECK, 15 внешних ключей, комментарии |
| `lab4_parking_data.sql` | лабораторная работа № 4 — вставка (91 строка), обновление и удаление данных |

**Вспомогательные файлы** (каталог `test`) — нужны для раздела
«Результаты» отчёта, самой работой не являются:

| Файл | Назначение |
|---|---|
| `test\integrity_tests.sql` | 12 проверок ограничений целостности |
| `test\structure_report.sql` | структура БД, каскадные правила, контрольные запросы |

**Прочее:**

| Файл | Назначение |
|---|---|
| `run_all.ps1` | автоматический прогон всех скриптов |
| `log\` | протоколы выполнения |
| `ОТЧЁТ_РГР_Автостоянка.md` | текст отчёта; открыть в Word и вставить скриншоты |
