# СОДЕРЖАНИЕ

# ВВЕДЕНИЕ

Цель работы — освоить создание и связывание таблиц базы данных в среде PostgreSQL, а также операции вставки, обновления и удаления данных.

Задание включает два этапа. Сначала выполняется учебный пример из пособия: создание семи связанных таблиц базы данных `sales`. Затем по индивидуальному варианту (вариант 11, «Автостоянка») в базе `parking` создаются девять таблиц, определяются ограничения целостности и внешние ключи, таблицы заполняются данными, после чего данные обновляются и удаляются. СУБД — PostgreSQL 16, клиентское приложение — pgAdmin 4.

# ОСНОВНАЯ ЧАСТЬ

## Учебный пример: база данных sales

Скрипт `lab3_sales_tables.sql` выполняется после подключения к базе данных `sales`, созданной в лабораторной работе № 2. Таблицы создаются в порядке от родительских отношений к дочерним, а внешние ключи определяются отдельными инструкциями `ALTER TABLE` после создания всех таблиц.

Таблица: Таблицы учебной базы данных sales

| Таблица | Назначение | Внешние ключи |
|---|---|---|
| categories | категории товаров | cat_overcat → categories (рекурсивная связь) |
| manufacturers | производители | — |
| products | товары | prod_cat_ID → categories, prod_man_ID → manufacturers |
| customers | заказчики | — |
| employees | сотрудники | — |
| orders | заказы | ord_cust_ID → customers, ord_emp_ID → employees |
| items | позиции заказов | item_ord_ID → orders, item_prod_ID → products |

Пример создания таблицы и определения внешнего ключа:

Листинг: Создание таблицы products и её внешнего ключа

```sql
CREATE TABLE products (
    prod_ID     integer NOT NULL,
    prod_name   text NOT NULL,
    prod_price  numeric(8,2) NOT NULL,
    prod_rest   integer NOT NULL,
    prod_cat_ID integer NOT NULL,
    prod_man_ID integer NOT NULL,
    CONSTRAINT products_PK PRIMARY KEY (prod_ID)
);

ALTER TABLE products
ADD CONSTRAINT products_FK1 FOREIGN KEY (prod_cat_ID)
REFERENCES categories (cat_ID)
ON DELETE CASCADE
ON UPDATE CASCADE;
```

Все семь таблиц связаны семью внешними ключами с правилами `ON DELETE CASCADE` и `ON UPDATE CASCADE`.

## Индивидуальное задание: создание таблиц базы данных parking

Скрипт `lab3_parking_tables.sql` выполняется после подключения к базе данных `parking` (`\c parking`). Он создаёт девять таблиц, затем добавляет ограничения. Состав таблиц и их связи приведены в таблице 2.

Таблица: Таблицы базы данных parking

| Таблица | Назначение | Внешние ключи |
|---|---|---|
| vehicle_categories | категории транспортных средств | — |
| clients | клиенты (физические и юридические лица) | — |
| employees | сотрудники | emp_chief_ID → employees (рекурсивная связь) |
| vehicles | транспортные средства | veh_cat_ID → vehicle_categories, veh_client_ID → clients |
| places | машино-места | pl_cat_ID → vehicle_categories |
| tariffs | тарифы | tar_cat_ID → vehicle_categories |
| contracts | договоры с клиентами | клиент, ТС, место, тариф, сотрудник (5 ключей) |
| payments | квитанции об оплате | pay_contr_ID → contracts, pay_emp_ID → employees |
| passages | журнал проездов | pass_veh_ID, pass_contr_ID, pass_place_ID (допускают NULL) |

Ограничения, кроме `NOT NULL` и `PRIMARY KEY`, добавляются отдельными запросами `ALTER TABLE`: так запрос `CREATE TABLE` проще читать, а ограничения проще изменять и удалять. Полные тексты запросов приведены в отчёте по лабораторной работе № 2 и в файле `lab3_parking_tables.sql`. Итог выполнения скрипта: девять таблиц, 8 ограничений `UNIQUE`, 8 значений `DEFAULT`, 19 ограничений `CHECK` и 15 внешних ключей (9 + 8 + 19 + 15 = 51 ограничение без учёта `DEFAULT`).

Фрагмент определения ограничений:

Листинг: Ограничения уникальности, значения по умолчанию и проверки

```sql
ALTER TABLE vehicles ADD CONSTRAINT vehicles_UK UNIQUE (veh_plate);
ALTER TABLE places   ADD CONSTRAINT places_UK   UNIQUE (pl_sector, pl_number);

ALTER TABLE places    ALTER COLUMN pl_status    SET DEFAULT 'свободно';
ALTER TABLE contracts ALTER COLUMN contr_status SET DEFAULT 'оформлен';

ALTER TABLE contracts ADD CONSTRAINT contracts_CK_dates
CHECK (contr_end IS NULL OR contr_end >= contr_start);
```

## Вставка данных

Листинг: Вставка категорий, сотрудников и клиентов (фрагмент)

## Обновление данных

Запрос `UPDATE` без условия `WHERE` изменит все строки таблицы, поэтому в каждом запросе условие указано явно.

Листинг: Обновление данных

```sql
UPDATE clients
   SET cl_discount = 10
 WHERE cl_ID = 4;

UPDATE clients
   SET cl_phone = '+79139990077',
       cl_email = 'timofeev@mail.ru'
 WHERE cl_ID = 7;

UPDATE vehicles
   SET veh_color = 'серебристый'
 WHERE veh_plate = 'М654СТ55';

UPDATE employees
   SET emp_position = 'старший кассир'
 WHERE emp_ID = 3;
```

Тариф изменяется в два шага: действие старого тарифа закрывается датой, затем вводится новый. Так сохраняется история цен, на которую ссылаются прежние договоры.

Листинг: Повышение тарифа на 10 %

```sql
UPDATE tariffs
   SET tar_date_to = '2024-12-31'
 WHERE tar_ID = 3;

INSERT INTO tariffs (tar_ID, tar_name, tar_period, tar_price, tar_cat_ID, tar_date_from, tar_date_to)
     VALUES (7, 'Месячный, легковой', 'месяц', 4950.00, 1, '2025-01-01', NULL);
```

После обновления число строк в таблице `tariffs` увеличилось с 6 до 7.

## Удаление данных

Для большинства связей задано правило `ON DELETE CASCADE`, поэтому удаление родительской строки удаляет и зависимые строки. Демонстрационные удаления выполнены внутри транзакции и отменены командой `ROLLBACK`, чтобы контрольный набор данных остался неизменным.

Листинг: Удаление данных в транзакции

```sql
BEGIN;

-- 3.1. строка без зависимостей: свободное машино-место C-2
DELETE FROM places
 WHERE pl_sector = 'C' AND pl_number = 2;

-- 3.2. строка с зависимостями: расторгнутый договор Д-2024/008
DELETE FROM contracts
 WHERE contr_number = 'Д-2024/008';

-- 3.3. группа строк по условию: низкая достоверность распознавания
DELETE FROM passages
 WHERE pass_confidence < 0.700;

ROLLBACK;
```

Результаты, полученные в протоколе выполнения, приведены в таблице 4.

Таблица: Результаты удаления данных

| Удаление | Запрос | Число строк до и после |
|---|---|---|
| Строка без зависимостей | место C-2 | мест: 12 → 11 |
| Строка с зависимостями | договор Д-2024/008 | квитанций: 16 → 15 (каскадное удаление квитанции) |
| Группа строк по условию | проезды с достоверностью ниже 0,7 | журнал проездов: 20 → 17 (3 строки) |

После `ROLLBACK` контрольный запрос показывает прежнее содержимое таблиц: все удаления отменены.
